# RigOne 1.11.7 — Auto runs survive a restart

*Released on 2026-10-28.*

Auto runs survive a restart and spend less time rerunning checks that already passed.

- Goals that were running when RigOne quit, crashed or the Mac restarted resume on their own when RigOne opens again. Settings → Auto has a switch to turn this off.
- Quitting RigOne while steps are still running asks first.
- A retry after an interrupted or failed attempt starts from that attempt's saved work instead of from scratch, when nothing else changed in the meantime.
- A check can be split into parts. On a repair turn, parts whose inputs did not change reuse their earlier pass, and parts that failed last time run first.
- A test that fails outside the files a step changed no longer sends the author back to fix it. RigOne reruns it alone and on the starting commit, and the run log says which failures were unstable and which already failed before the change.
- Each acceptance criterion can name the test that proves it. The check before the review runs that test, and the reviewer sees the result next to the criterion.
- When a check is missing a required test, its message names the tests that did run, so a misnamed test is fixed in one turn.
- Before a run starts, Auto warns when a check names a test module, test file or script that does not exist and that no step will create.
- Build caches from checks no longer pile up in the evidence folder, and leftover work copies of interrupted runs drop their build folders after three days.
- A finished Auto goal no longer shows as working in the sidebar.
- Everything from 1.11.6 is included.

To update, download the macOS Apple Silicon DMG and replace RigOne in `/Applications`.
