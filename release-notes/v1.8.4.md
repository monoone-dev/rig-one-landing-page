# RigOne 1.8.4 — Auto finishes work instead of starting over

*Released on 2026-10-22.*

This update makes Auto finish work instead of starting over, and lets it run on computers without YOLO.

- RigOne no longer wraps any step in its own sandbox, so agents always see their own sign-ins: no more "Not logged in" from Claude or "Operation not permitted" from Codex.
- The full access (YOLO) switch now only chooses the agents' own permission mode. Off, Claude edits without asking and Codex works in its own workspace mode, so Auto still runs unattended.
- If Codex cannot start its own sandbox with YOLO off, Auto runs that step again with Claude or OpenCode.
- When a check, gate or verifier does not pass, the same agent gets the error and fixes it in the same run, up to two times, instead of the run ending.
- A requirement that could not be measured is "don't know", not a failure.
- Failed web tests are run again alone; if they pass, the step says "Failed only under load" and the run continues.
- A failed check shows its real error lines, also when it stopped before any test ran.
- Every RigOne process gets the folder's GitHub account through its environment, so private git dependencies no longer ask for a password.
- Secrets you paste into the Lead chat are hidden in statuses and tool results.
- The Lead uses the agent apps you name, keeps working instead of refusing plans, and says "Auto is still working" instead of "Done" while parts are still running.

To update, download the macOS Apple Silicon DMG and replace RigOne in `/Applications`.
