# RigOne 1.2.0 — Auto finishes real work

*Released on 2026-10-08.*

Auto now builds a goal into ordinary workflows and carries it to a verified result. In tests on a
real Rust and Angular app it took a small UI change, a full-stack feature and a six-part feature
(research, design, backend, frontend, fixes and the whole end-to-end suite) from one sentence to a
checked result. Most of this release is about the agents having what they need to run. Where they
used to stop, they now continue.

**Auto workflows can do more.**

- **Background apps.** A workflow can start your app in the background for checks and reviews.
- **Lead commands.** The Lead can run its own commands and show them as "Lead's command passed".
  Only your saved checks show "Checks passed".
- **Questions in the middle.** A workflow can stop and ask you something, then carry your answer
  to the next step.
- **Access.**
  - The Lead may let a step edit and run commands inside its own copy without asking.
  - Writing outside the copy and extra Connections need your approval once.
  - Pushes and pull requests are checked against the folder's GitHub account and show
    "Pushed as …".
- **Retries.** A new attempt can start from the saved work of an earlier one instead of writing
  everything again.

**RigOne decides when work is verified, not the Lead.** A process counts as done only when its
checks and review prove it. A review that fails reopens exactly the result it judged.

**Steps run where tools expect them.**

- **Codex and Claude.** Codex steps run commands under RigOne's file boundary, and Claude's shell
  works there too.
- **Copies outside your project.** Steps no longer hit "operation not permitted" in build tools
  such as Angular, npm and Prettier.
- **Connections.** They start under the boundary. Browser tools get their own profile, and a
  Connection that fails to start leaves a note while the step goes on.
- **Files other apps rewrite.** Sign-in and hidden files that other apps rewrite no longer stop a
  step from starting.
- **Shared locks.** A project's setup can declare shared folders, such as a machine-wide build
  lock, that steps may use.

**The Lead plans with less.** The Lead reads only the rules of the roles it picks, and
Connections load when it needs them. In our tests a planning session started at about a third of
its earlier size. The Lead's notes now carry from one goal to the next in the same project.

**Waiting and stopping behave.**

- A question for you no longer times out after 30 minutes.
- A question that is no longer waiting leaves the window.
- A Lead waiting on its own long test run is no longer stopped as idle.
- After you stop a goal, the header shows the goal's run instead of your default workflow.

**Results stay clean.**

- Build caches and other ignored files no longer count as out-of-scope changes. A `.gitignore`
  written by an agent hides nothing.
- Result commits use a conventional message such as `feat(trash): …`, and the Lead can choose it.
- A tool an agent was refused is shown as a note, not as a failed step.

One trade-off: Codex commands may reach the network in every role, the same as Claude's shell.
Roles without web access still have Codex's web search turned off.

To update, download the macOS Apple Silicon DMG and replace RigOne in `/Applications`.
