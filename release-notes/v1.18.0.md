# RigOne 1.18.0 — Auto loses less finished work

*Released on 2026-11-11.*

Auto loses less finished work, starts steps with less context, and stops asking about usage limits that were never reached.

- The Lead starts again in projects with many Lead notes: a folder with more than 128 notes no longer stops every Lead from starting.
- A start is no longer held with "confirmed room below 95% usage" because the usage reading went stale while the start waited for a place. Limits are read right before the decision.
- A start without usage room no longer asks you: it waits a short time, then the Lead is told and plans again. You are asked only after three such starts in a row.
- Settings has a usage limits section: switch the warning on or off and choose the percent (50 to 100) from which RigOne warns and moves work to another agent app.
- When a workflow fails, the Lead is told which step failed, why, and what RigOne recorded, instead of one general sentence.
- When the computer, not the code, ended a run (Docker, a busy port, the test database, a killed process, a full disk), RigOne restarts the part once by itself and asks you after two endings with the same cause.
- A part counts as done elsewhere only when its commit is on the remote default branch.
- A reviewer that runs after a check now gets the author's handoff and the change itself. A check hands over its verdict, counts and failed test names, with the full log as a path.
- The Lead starts a checked plan by its process ID instead of sending the plan again, and gets a short result packet when a workflow ends.
- An agent file can say which of your own plugins and MCP servers the agent gets: all, chosen ones, or none. Without that line every agent, the Lead included, gets all of them as before.
- Step effort has a ceiling, the last judging step runs on a different agent app than the author when one has room, and the reflection after a run uses a light model.
- Reference sets without requirements are listed by title; agents read them through the context tools when they need them.
- Rust builds use every build slot again: slots left without an owner are taken and cleared at start-up.
- A build that cannot use the project's shared build folder starts from the project's last build output instead of from nothing.
- Copies and workshops share one Git mirror per project, a pinned sibling repository is cloned from one kept tree, and copies of replaced attempts are freed within the hour.
- The goal file is much smaller: the before and after text of a gate change is stored beside it, and a gate change is recorded only for files that are checks by their path.
- Opening one goal reads one goal file, and the list of goals reads short headers.
- Boards no longer rewrite an unchanged board file on every poll.
- Remote reads a saved conversation when it is first used, not at start, and records run lines only while Remote is on and a device is paired.
- Provider caches of ended runs and stale Lead skill folders are freed, and an idle goal no longer keeps re-creatable run data on disk.
- Two security advisories in dependencies are cleared.

A run that starts while Remote is off does not appear on the phone after you switch Remote on.

To update, open Settings → About and install it. From a version without the in-app update, download the macOS Apple Silicon DMG once and replace RigOne in `/Applications`.
